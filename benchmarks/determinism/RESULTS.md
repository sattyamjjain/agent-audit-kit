## Contrast (cited, not re-run)

This is a self-benchmark of AAK. The tools below are **scope-cited from their own public docs — not re-run here**, and no competitor number is fabricated. The point is architectural: an LLM judge in the finding path forfeits the byte-identical-re-run guarantee above.

- **Cisco DefenseClaw** (open-source, Apache-2.0) — its own docs describe runtime guardrails that inspect prompts/completions/tool calls with *“regex rules, policy, optional **LLM judge**”* and a Skill Scanner combining pattern rules with *LLM-as-a-judge* ([cisco-ai-defense/defenseclaw](https://github.com/cisco-ai-defense/defenseclaw), [docs](https://cisco-ai-defense.github.io/docs/defenseclaw)).
- **Snyk Agent Scan** — LLM-assisted analysis (per Snyk's product materials; the static-rule count is shown as `~30` in the comparison table above).

LLM-as-judge evaluation is independently documented to vary run-to-run and to carry reliability/bias concerns — e.g. *“The Coin Flip Judge? Reliability and Bias in LLM-as-a-Judge Evaluation”* ([arXiv:2606.13685](https://arxiv.org/abs/2606.13685)). We deliberately quote **no specific variance percentage** for the tools above: we did not re-run them, so any number would be invented. What we *can* prove is our own side — the table above, reproducible from this repo.
