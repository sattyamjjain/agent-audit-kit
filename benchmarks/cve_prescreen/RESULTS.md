## Limitations

- One run, one sample per record, at the CLI's default effort. Run-to-run variance was not measured, so a difference of a few records between two prompt versions is noise.
- The ground truth is the maintainer's dispositions read by rules (`ground_truth.py`). Four records the rules could not read (`OVERRIDES`) and the six noise records (`NOISE`) were settled by the agent that built this benchmark, from the maintainer's own notes. The maintainer has not reviewed these labels.
- The prompt was written by someone who had read the ledger, then frozen before any backtest call. It is an informed prompt, not a blind one, and it was not changed after the run.
- The verifier was corrected after the run, from the run's own mismatches: CNA placeholder products such as `n/a` stopped counting as expected packages, and a value that differs from its field only in whitespace (a no-break space typed as a space) is reported as `whitespace` instead of `invented`. Model outputs were not touched; extraction was re-scored from them.
- AAK's read surface changed inside the window: container image tags became readable on 2026-10-03, and the Go arm of the STDIO command-injection family landed on 2026-09-15. The prompt describes today's surface, so a record closed as out of scope before a reader existed can disagree for that reason alone. SiYuan, MaxKB, Coroot and Lightdash were closed for having no PyPI or npm artifact before image tags were readable; whether the maintainer would pin their images today is not known.
- The commonest model error is asserting that a product is published on PyPI, npm or a container registry when no structured field shows it ("likely an npm package", a Docker image name the record never mentions). The post-hoc split under the confusion matrix shows what that does to version-pin precision. The structured data can be wrong as well: GHSA names pip `onyx` for the Onyx AI platform, which the ledger records as an unrelated PyPI project, so even a copied package needs its registry identity checked.
- version-pin against new-detection is partly maintainer judgment the prompt does not encode: the ledger says a class rule was chosen over a one-package pin for a recurring shape (argocd-mcp, @ooples/token-optimizer-mcp), and a general LLM-app bug with no MCP surface was closed as out of scope although the package is on PyPI (langchain-chatchat).
- The maintainer's own labels shifted over the window: a source-only MCP server whose shape a detection rule covers was closed as out of scope in August (mcp-dominican-layer, mcp-rdf-explorer) and recorded against the rule in September (MCP Documentation Server). The ground truth keeps each record's label as decided.
- Noise has six positives, so its recall interval is wide; its precision is measured on every other record in the window.
- NVD, GHSA and OSV were read on 2026-10-12, after the dispositions. A record revised since triage shows the model today's text, not what the maintainer read.
- Cost is the CLI's list-price `total_cost_usd`, not a charge on the subscription. Wall time includes CLI start-up; one Haiku call hung until the 300 s timeout and is counted in the noise stage's mean, so read its median.
- `needs-human` never appears in the final ground truth, because every deferral in the window was resolved, so a `needs-human` answer can only count as an abstention.
