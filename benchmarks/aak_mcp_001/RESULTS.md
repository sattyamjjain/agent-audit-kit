# AAK-MCP-001 measurement — AgentAuditKit

> Steps 0 and 1 generated by [`measure.py`](measure.py) (offline, deterministic, no
> LLM; it needs the gitignored `benchmarks/data` crawl) and [`probe.py`](probe.py)
> (one opt-in network run, **2026-10-11 UTC**). Steps 2 and 3 are pending. The
> probe, the joined headline and the Step 3 sample measure the rule as State of MCP
> report v1.0 shipped it, on its 1,311 hits. Report v1.1 then changed the rule: it
> no longer reports a loopback host, and it recognises `*_API_KEY` and
> `-Subscription-Key` headers. Steps 0 and 1 are re-derived on the v1.1 rule and
> scan (2026-10-15); the probe, the sample and their tables are kept as recorded.

## Status: Steps 2 and 3 pending

No true-positive rate for `AAK-MCP-001` is stated here, and none may be until
every verdict in [`verdicts.json`](verdicts.json) is set by hand. What this page
does establish is factual: what the published numbers are made of, what the
hits' URLs say, and what the servers behind them answered when asked, without a
credential, to start an MCP session.

`AAK-MCP-001` fires CRITICAL on every URL server whose config carries no
recognized auth header. A hosted server that follows the MCP authorization
specification puts no credential in the config: the client gets HTTP 401 with a
`WWW-Authenticate` challenge and runs OAuth at connect time. Its correct config
fires too. The question is how much of the State of MCP report's headline that
accounts for.

## Headline

On 2026-10-11, of the 1,311 `AAK-MCP-001` hits behind report v1.0's headline,
**514 (39.2%) point at a server that turned an unauthenticated client away**
(HTTP 401 or 403 for 501 of them, 402 for 13) and **448 (34.2%) at one that
accepted it** (a JSON-RPC result to the `initialize`). Another 49 (3.7%) point
at a loopback or private host. The rest did not answer usefully (169 no DNS
answer, 82 another HTTP answer, 17 no HTTP answer) or were not probed (32).

| If this does not count as a critical `AAK-MCP-001` hit | Configs with a critical finding | Share of 2,303 |
|---|---:|---:|
| Nothing (as published) | 1,213 | 52.7% |
| A hit on a server that refused the unauthenticated client | 773 | 33.6% |
| ...or on a loopback or private host | 738 | 32.0% |
| Anything but a hit on a server that accepted the unauthenticated client | 452 | 19.6% |

These rows are v1.0's. Report v1.1 exempts a loopback host in the rule itself, so
its headline already leaves out the loopback hits counted here; Step 0 has its
figures.

These are facts about the servers, not verdicts. A refusing server is not an
unauthenticated one, and 424 of the 458 refusing endpoints said so with a
`Bearer` challenge, so the first exemption needs little judgement; the other 34
refusals carry no challenge, and a 403 can also be a bot filter rather than
authentication. An accepting server can still be public by design
(documentation search, public data), and deciding which ones are is what Steps
2 and 3 are for.

The report's other auth sentence does not survive the same check: "not a single
public server serves the discovery document the ratified auth spec expects". That
figure counts configs that *mention* RFC 9728 discovery (`AAK-OAUTH-008` reads
config text). Asked directly, **564 of the 992 endpoints that answered DNS
(613 hits) served RFC 9728 protected-resource metadata**, and 539 of those
named an authorization server. The report's corpus is from 2026-07-26 and the
probe ran 77 days later, so some servers may have added it since; the sentence
was never a measurement of servers either way.

## Step 0: the published numbers, re-derived

`make report` rebuilds `research/state-of-mcp-2026/results.json` from the crawl
and the committed registry manifest. A fresh offline run of it was
**byte-identical** to the committed file, and `measure.py`, which re-scans the
same corpus in the same order with its own per-config bookkeeping, agrees on
every headline figure:

| Figure | `results.json` | Fresh scan |
|---|---:|---:|
| Distinct configs scanned | 2,303 | 2,303 |
| Configs with `AAK-MCP-001` | 1,166 | 1,166 |
| Configs with a critical finding | 1,184 | 1,184 |
| Share with a critical finding | 51.4% | 51.4% |

All 1,166 `AAK-MCP-001` configs are among the 1,184. Those 1,166 configs carry
**1,263 hits** (findings: one per server entry the rule fires on): 1,136
configs have one, 30 have between 2 and 11. Only **19 configs (0.8%) carry a
critical finding other than `AAK-MCP-001`**: `AAK-MCP-002` (9), four CVE version
pins (K8s 2, n8n-MCP 2, GitLab 1, Ruflo 1), `AAK-SECRET-008` (2),
`AAK-TRANSPORT-001` (1), `AAK-POISON-001` (1) and `AAK-POISON-002` (1). Eighteen of
the 1,184 have no `AAK-MCP-001` hit at all, and 1 has both. In v1.0 these were
1,311 hits on 1,201 configs, and 14 configs with another critical finding.

The headline under counterfactual versions of the rule, from the URLs alone:

| Scenario | Configs with a critical finding | Share | `AAK-MCP-001` still critical |
|---|---:|---:|---:|
| The rule as shipped | 1,184 | 51.4% | 1,166 |
| Every `AAK-MCP-001` hit is a false positive | 19 | 0.8% | 0 |
| Loopback hosts exempt | 1,184 | 51.4% | 1,166 |
| Loopback and private-network hosts exempt | 1,184 | 51.4% | 1,165 |
| https without a header downgraded below critical | 22 | 1.0% | 4 |
| Loopback exempt and https downgraded | 22 | 1.0% | 4 |

The headline is, to within 19 configs, `AAK-MCP-001`. The rule exempts loopback
itself since v1.1, so that scenario now equals the rule as shipped, and exempting
private hosts as well leaves `AAK-MCP-001` critical on one config fewer.
Downgrading https without a header still removes almost all of it: the 4
plain-http hits left are all on private hosts, and no public server in the
corpus is reached over cleartext.

## Step 1: what the hits are

### From the URL (deterministic, [`results.json`](results.json))

| Host class / scheme | Hits |
|---|---:|
| public / https | 1,251 |
| private network / http | 4 |
| template variable / https | 4 |
| template variable / no scheme | 3 |
| placeholder name / https | 1 |

No hit is on a loopback host: the rule stopped reporting one in v1.1, which took
out v1.0's 45 loopback hits. 1,040 hits come from the MCP Registry and 223 from
the GitHub crawl. Of the registry hits, 1,037 have registry `auth_mode` `none`
(the other 3, `header-nonsecret`). `none` is the one auth mode the false-positive
benchmark's benign predicate excludes, which is why that benchmark never saw this
class. By transport: 1,234 streamable HTTP and 29 SSE.

Two smaller classes where authentication is present, or expected, in a form the
rule does not read:

- **A credential in the URL**: 15 hits (4 literal, 11 a placeholder such as
  `?api_key={api_key}`), in the query for 6 and the path for 9.
- **An auth header the rule does not recognize**: 3 hits whose header name says
  credential but matches neither recognized family, plus 3 recognized custom
  headers holding a hardcoded literal, which the rule fires on by design. In v1.0
  the first class held 8 hits, five of them an underscore-separated `*_api_key`
  that v1.1 recognises.

### From the servers (probe, [`probe-summary.json`](probe-summary.json))

This section and the next describe v1.0's 1,311 hits, as probed on 2026-10-11.
The probe sent each distinct public https endpoint one unauthenticated MCP
`initialize` and GETs of its RFC 9728 metadata (method below). 1,230 hits map to
**1,157 distinct endpoints on 1,081 hosts**; the other 81 hits were not probed:
49 non-public hosts, 14 with a credential in the URL, 8 more skipped as possible
credentials (a query value that is not a plain word), 7 template hosts, 2
templates elsewhere in the URL and 1 placeholder host.

| `initialize` answer | Endpoints | Hits |
|---|---:|---:|
| HTTP 401 or 403 (refused) | 458 | 501 |
| JSON-RPC result (accepted) | 423 | 448 |
| No DNS answer | 165 | 169 |
| Not found (404, 410) | 38 | 39 |
| Redirect, not followed | 17 | 17 |
| HTTP 402 (payment gate) | 13 | 13 |
| Server error (5xx) | 13 | 13 |
| Timeout after one retry | 11 | 11 |
| Method not allowed (405) | 8 | 8 |
| TLS failure | 6 | 6 |
| Other 4xx | 3 | 3 |
| Other 2xx without a JSON-RPC result | 2 | 2 |

Of the 458 refusing endpoints, 424 sent a `Bearer` challenge, 406 named a
`resource_metadata` URL in it (RFC 9728 section 5.1), and 425 served
protected-resource metadata on at least one well-known variant, 420 of them
naming an authorization server. That is the MCP authorization flow, working as
specified, on configs the rule reports as unauthenticated. Of the 423 accepting
endpoints, 120 also serve the metadata, which would fit servers that
authenticate per tool call or offer optional sign-in; and 87 issued a protocol
session id.
The accepting servers negotiated protocol 2025-11-25 (283), 2025-06-18 (73),
2025-03-26 (34), 2024-11-05 (32) and one unlisted version.

None of the 1,081 hosts resolved to a private or reserved address. Of the 165
endpoints without a DNS answer, 125 are one publisher's family of per-country
subdomains. Median `initialize` latency was 675 ms (p90 1,274 ms).

## Step 2: model labels (pending)

[`measure.py`](measure.py) `--population-out` writes the labeler's input:
one redacted record per hit with the config id and source, server name, URL,
the registry's title, description, auth mode and remotes (from the raw pages of
the same 2026-07-26 crawl), and the probe's answers. Every credential-shaped
value is removed before the file is written, and the write is refused if any
of an independent set of secret patterns survives; the tests prove it by
planting secrets in every place a config hides one. The file holds third-party
records and stays outside the repository.

## Step 3: blind human adjudication (pending)

A stratified random sample of **150 of the 1,311 hits**, drawn by
[`sample.py`](sample.py) with seed `aak-mcp-001/2026-10-12`, recorded with its
frame in [`sample.json`](sample.json). Within each stratum the hits with the
lowest SHA-256 of seed and hit id are taken, so the draw can be recomputed from
the committed frame in any language. Allocation is proportional, with a floor
of 4 per stratum:

| Stratum | Population | Sample |
|---|---:|---:|
| Loopback or private host | 49 | 6 |
| Template, placeholder or unparseable host | 8 | 4 |
| Credential in the URL, or an unrecognized auth header | 23 | 4 |
| Public https, `initialize` refused (401/403) | 499 | 55 |
| Public https, `initialize` accepted | 442 | 49 |
| Public https, any other answer or none | 290 | 32 |

The sheet the maintainer reads lists each sampled hit's evidence in a
stratum-blind order, with no model or heuristic label, and carries the
[codebook](CODEBOOK.md). Verdicts go into [`verdicts.json`](verdicts.json),
directly or by `sample.py --import-csv` from the sheet's CSV twin. The codebook
has six codes: the five the brief named (`hosted-oauth`, `public-by-design`,
`loopback`, `truly-open`, `unknown`) and `auth-other`, for a server that
authenticates by something other than OAuth at connect time (an unrecognized
header, a key in the URL, a 402 gate). Only `truly-open` counts as a true
positive; merge `auth-other` into `hosted-oauth` if a five-code scheme is wanted,
since neither is open.

[`ppi.py`](ppi.py) then estimates the share of hits that are true positives by
prediction-powered inference (Angelopoulos, Bates, Fannjiang, Jordan and Zrnic,
"Prediction-powered inference", *Science* 382, 2023; arXiv:2301.09633): the
model's labels on all 1,311 hits, corrected by the measured model-human
disagreement on the sample, next to the human-only estimate with a Wilson
interval. Until every verdict is set it prints "pending" and nothing else.

## Method

### Reuse, not reimplementation

`measure.py` iterates the corpus with `run_report.py`'s own `_config_sources`,
`_content_key` and `_scan_text`, so its configs are the report's configs. It
re-derives each config's hits with the rule's own helpers
(`mcp_config._as_str`, `_server_declares_auth`, `is_loopback_url`, over the
server maps `iter_mcp_servers` yields) and checks them, evidence string for
evidence string, against the findings the engine emitted; a single disagreement
aborts the run. The rule's code is imported, never copied. That check is how
v1.1's loopback exemption surfaced here: until these helpers followed the rule,
the run stopped on a config with 2 derived hits and 1 emitted.

### The probe

[`probe.py`](probe.py) sends exactly two kinds of request, and only with
`--probe`:

1. one unauthenticated JSON-RPC `initialize` POST (`Accept: application/json,
   text/event-stream`, `protocolVersion` 2025-11-25, the newest revision whose
   lifecycle makes `initialize` the first message; later revisions negotiate);
2. GETs of the RFC 9728 section 3.1 metadata URLs for the endpoint's path (the
   path-inserted form, and the root form the MCP authorization specification
   names as the fallback), plus the `resource_metadata` URL named in any
   `WWW-Authenticate` challenge.

It never follows a redirect, never fetches authorization-server metadata and
never sends `notifications/initialized`. A URL carrying a credential (userinfo,
a credential-named or credential-shaped query parameter or path segment) is
never sent; every host is resolved first, skipped if any address is
non-public, and the connection is pinned to the vetted address with TLS still
verified against the host name. At most 4 connections at once, one in flight
and at least 1 s between request starts per host, a 10 s timeout, one retry
and only on a network error, 64 KiB read at most, and the User-Agent
`agent-audit-kit-research (+https://github.com/sattyamjjain/agent-audit-kit)`.
The raw log from the run checks itself against those limits: the shortest gap
between two requests to one host was 1.0 s, and never more than 4 requests were
in flight. 2,834 requests went out in 13 minutes: 1,004 `initialize` POSTs (12
of them retries) and 1,830 metadata GETs (5 retries). The raw log is outside
the repository; `probe-summary.json` and `probe-headline.json` hold counts
only, with no host, URL or response body.

### Hits and hit ids

A hit is one `AAK-MCP-001` finding, one (config, server entry) pair. Its id is
the first 16 hex digits of SHA-256 over the config's content key and the server
name: stable, re-derivable from the corpus, and meaningless without it.

## Limitations

- **One probe, one day, 77 days after the corpus.** Servers that changed between
  2026-07-26 and 2026-10-11 are measured as they were on the later date.
- **`initialize` is not the whole session.** A server that accepts an
  unauthenticated `initialize` may still authenticate each tool call, and the
  probe sends nothing further by design. "Accepted" is the strongest open
  signal it can see, not proof of an open tool surface.
- **SSE-transport servers** (41 hits, 12 of them on loopback) expect a GET to
  open a stream, which the probe does not send. Of the 29 public ones, 15
  answered the POST with 404 or 405 and land in the "other" classes, 7 accepted
  it, 5 refused it and 2 gave no answer.
- **The credential-in-URL heuristics are conservative.** Eight endpoints
  were skipped because a query value was not a plain word (comma-separated
  feature lists, for instance), not because it was shown to be a credential.
- **Config-level versus hit-level.** The PPI estimand is the share of hits. The
  headline counts configs; 39 of v1.0's 1,201 held more than one hit (30 of
  v1.1's 1,166 do), so the two differ slightly, and the per-config consequence of
  a verdict is derived, not sampled.
- **One rater, when there is one.** The adjudication will have a single rater,
  as the MCP benchmark's does, and no inter-rater statistic.

## Reproduce

```bash
# Step 0 and the URL classes (offline; needs the crawl; a worktree can point at another checkout's)
AAK_MCP001_CORPUS=benchmarks/data python benchmarks/aak_mcp_001/measure.py --check

# The probe (network, opt-in) and its aggregate
python benchmarks/aak_mcp_001/probe.py                                   # plan only, sends nothing
python benchmarks/aak_mcp_001/probe.py --probe --raw-out /outside/repo/probe-raw.jsonl
python benchmarks/aak_mcp_001/probe.py --summarize /outside/repo/probe-raw.jsonl --write
python benchmarks/aak_mcp_001/measure.py --write --probe-raw /outside/repo/probe-raw.jsonl \
    --population-out /outside/repo/population.jsonl

# The sample and the blind sheet
python benchmarks/aak_mcp_001/sample.py --population /outside/repo/population.jsonl --sheet-dir /outside/repo

# After adjudication
python benchmarks/aak_mcp_001/ppi.py --model-labels /outside/repo/model-labels.jsonl
```
