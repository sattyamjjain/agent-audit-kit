    AAK-AGENT-SHARED-RES-AUTHZ-001: Mutating tool on a shared/multi-agent resource lacks a per-actor authorization parameter

    Severity
    HIGH
    Category
    Trust Boundaries (trust-boundary)
    Scanner
    agent_audit_kit/scanners/shared_resource_authz.py
    Auto-fixable
    No.
    SARIF name
    SharedResourceMissingActorAuthz

    What it detects

    A tool/function/MCP descriptor exposes a mutating operation (delete / remove / edit / update / overwrite / move) on a file, record, or resource that is reachable in a shared or multi-agent context, yet its input schema carries no owner / actor / authorization / permission field. Any agent that can call the tool can therefore mutate another principal's resource — there is nothing in the call surface that scopes the action to the caller. This is the CVE-2026-44654 broken-access-control class (LibreChat <= 0.8.3: a shared-agent editor could delete file records via DELETE /api/files that the owner had reused across multiple agents; CWE-863 Incorrect Authorization, CVSS 8.1). The shared context is inferred from a multi-agent config (an agents collection with >1 member, or a shared / scope: shared|workspace|team marker) or from shared-resource language in the tool's own name/description.

    How to fix

    Add and enforce a per-actor authorization parameter (e.g. owner_id, actor, on_behalf_of, authorization) and check it server-side so a tool call can only mutate resources the calling principal owns. Do not rely on the agent to self-restrict. If the resource is genuinely global and every agent is authorized to mutate it, annotate the tool "x-aak-shared-authz": "global-ok" to document the decision and suppress this finding.

    To confirm the finding is gone, report only this rule:

    agent-audit-kit scan . --rules AAK-AGENT-SHARED-RES-AUTHZ-001

    Limitations

    Reads JSON files only, taking a tool's name and description from keys written in exactly that case (a "Description" key hides the text), and matches words in any case. It fires on a tool whose name and description contain one of delete, remove, edit, update, overwrite or move as a whole word, whose description has deletes, removes or overwrites, or updates, edits or moves followed by an article or quantifier (a, an, the, this, that, these, those, its, their, your, any, all, each, every, one, existing, specified, selected, given or multiple), or whose name starts with one of the six verbs (delete_shared_file, deleteSharedFile), and one of file, record, resource, document, doc, entry, item, object, row, entity, note, message, artifact, dataset, memory, conversation or thread with at most a trailing s (files, not entries), when the file declares a shared context (shared: true, more than one agent, or a scope of shared, workspace, team, org or organization) or the tool's own text contains shared, multi-agent, cross-agent, team (as a whole word), workspace, collaborat*, other agents, reused across, org-wide or tenant (with _, - or nothing inside multi-agent, cross-agent and org-wide), and no property name contains owner, actor, principal, author, user_id, caller, authoriz*, permission, tenant, requested_by, on_behalf, requester or subject_id (with _, - or nothing between the words) or the whole word acl. Not reported: a description such as Updates notes in the team workspace, where no article follows the verb; a verb further into a snake_case or camelCase name (file_delete); a tool with any of those property names, whether or not its handler enforces it; a tool described without the shared words; and a tool declared in Python source.
